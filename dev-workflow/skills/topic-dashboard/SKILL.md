## Overview

This skill is a **thin wrapper around a deterministic generator**. It runs no workflow logic itself and parses no docs — the generator core ([`${CLAUDE_PLUGIN_ROOT}/skills/topic-dashboard/scripts/dashboard-core.js`](${CLAUDE_PLUGIN_ROOT}/skills/topic-dashboard/scripts/dashboard-core.js)) scans `docs/ref/<MODULE>/<TOPIC>/`, reads the topic docs + orchestrator ledger, and writes one self-contained HTML file to `.ai-tmp/topic-dashboard.html`.

Because it is deterministic, the page is **regenerable on demand** — run the skill (or the bare script) again to refresh it. It is also usable **without Claude at all** (`node <plugin-path>/skills/topic-dashboard/scripts/dashboard-core.js` from any adopting repo), which is what makes it reusable across repos.

## When to Use

**Use this skill when:**
- The human wants to **see all topics and their progress** in one page (monitoring / portfolio view).
- After session breaks, to get a whole-repo picture beyond a single topic's `topic-status`.
- A human reviewer wants a quick read of where every topic stands (phases, tests, deployment, pending gates).

**Do NOT use this skill when:**
- You need one topic's status with a next-step recommendation — use `topic-status` (the dashboard shows position, not next steps).
- You need to resume an orchestrated topic — the page shows ledger state; resuming is the orchestrator skill's job.
- No topic docs exist yet — the generator exits with an error; run `topic-init` first.

## Step 1 — Resolve the Repo Root

The working repo is the current working directory. Confirm `docs/ref/` exists there — if not, stop and tell the human: the dashboard scans the plugin's `docs/ref/<MODULE>/<TOPIC>/` convention, and this repo has no topics yet (suggest `topic-init` for the first topic).

---

## Step 2 — Ensure the Temp Folder Is Ignored

The output lands at `.ai-tmp/topic-dashboard.html` (repo root) per the temporary-artifacts rule (Mandatory reads #1). Check the repo's `.gitignore` contains a `.ai-tmp/` entry — if missing, add it (this is the rule's designated gitignore backstop) or, if `.gitignore` itself must not be edited, flag that to the human before generating.

---

## Step 3 — Run the Generator

Run the deterministic core (do NOT parse docs yourself — determinism is the point):

```bash
node "<CLAUDE_PLUGIN_ROOT>/skills/topic-dashboard/scripts/dashboard-core.js" "<repo-root>"
```

- Default output: `<repo-root>/.ai-tmp/topic-dashboard.html` (override with `--out <path>` if the human asks).
- Exit code 0 prints a one-line summary + the written path. Exit 1 = no `docs/ref/` found (Step 1 should have caught this).
- If the command errors, report the exact error — do not fall back to hand-assembling the page.

---

## Step 4 — Report & Hand Over

Report:
- The generator's one-line summary (topic count, orchestrated count, open-questions count).
- The output path.
- **Open the page for the human** (e.g. `start <path>` on Windows / `open <path>` on macOS — use the repo platform's command), or tell the human the path to open manually.
- One line on staleness: the page is a snapshot — rerun `/topic-dashboard` to refresh after progress changes.

---

## Constraints

- **Deterministic only** — never hand-parse docs or hand-write the page; always run the generator core. Never edit its output file.
- **Read-only for topic docs** — the generator reads the topic docs and writes only `.ai-tmp/topic-dashboard.html`. No doc is created or edited.
- **Never run `git commit` / `git push`** — the human owns all git operations.
- **Stack-agnostic & repo-agnostic** — the core knows only the `docs/ref/` convention and the documented table formats; it invents nothing for repo-specific layout.
- **"unparsed" is a feature** — a doc section that does not match the expected table format shows as unparsed in the page. Report it to the human; the doc is malformed and should be fixed, not guessed around.
